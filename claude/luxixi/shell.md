# Shell 脚本与运维操作规则

适用范围：bash / zsh 脚本编写、一次性运维命令、部署与清理操作。Nginx、Docker 专项规则分别见 `nginx.md`、`docker.md`。

## 破坏性操作红线

破坏性命令指 `rm`、`chown`、`chmod`、`mv`、`dd`、`truncate`、`>` 覆盖写，以及任何叠加 sudo 或通配符的状态变更命令。

- 禁止在破坏性命令中使用可能为空的变量；执行前必须校验非空（`"${VAR:?}"` 或 `[ -n "$VAR" ]`）——空变量叠加通配符会让 `"$BK"/*` 退化成 `/*`
- 破坏性命令执行前必须先 `echo` 预演展开结果，确认实际路径后再执行
- 禁止对系统路径（`/`、`/usr`、`/etc`、`/var` 等）执行递归或通配符 `chmod` / `chown`；确需修改系统文件权限时逐一列明路径，不加 `-R` 不用通配符
- 禁止给简单任务叠加它不需要的高风险步骤；备份文件放当前用户可写目录，不用 `sudo cp` 制造 root 属主文件再回头「补救」
- `rm -rf` 的目标必须是字面量路径或已校验变量，禁止出现含未校验变量的 `rm -rf "$DIR"/*` 形式
- 批量 / 递归操作先用 `ls` / `find` 打印目标清单确认范围，再执行实际动作

## 脚本健壮性

- bash 脚本头部使用 `set -euo pipefail`
- `set -e` 下警惕「中断点跳过了后续命令依赖的赋值」：前一步失败提前退出时，后续步骤读取的标记文件 / 变量可能为空，读取处必须再次校验
- 变量展开一律双引号包裹：`"$var"`、`"${arr[@]}"`
- 禁止解析 `ls` 输出遍历文件；用 glob 或 `find -print0 | xargs -0`
- 临时文件用 `mktemp` 创建，并用 `trap` 在退出时清理
- 脚本必须幂等：重复执行不产生叠加副作用（重复追加、重复创建、状态残留）
- 关键步骤失败时输出明确错误信息和上下文，不静默吞错

## 可移植性

- macOS（BSD 工具链）与 Linux（GNU 工具链）行为有差异（如 `sed -i`、`date`、`stat` 的参数），跨平台脚本必须声明目标平台或做兼容分支
- 不假设 bash 版本；macOS 自带 bash 3.2，用到关联数组等较新特性时显式声明版本依赖

## 文档查询

- shell 内建命令与系统工具的参数以本机 `man` 手册和 `--help` 输出为准，不凭记忆假设参数行为
- 本机可用 shellcheck 时，bash 脚本先通过校验再交付
